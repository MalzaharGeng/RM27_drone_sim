# 2026-11-04 场地贴图定稿

## 方案：整场一个 OBJ

贴地平面那条路走不通（前一晚的结论：要么 z-fighting，要么抬高后和台阶错位），
改成把整块场地导出成一个带 UV 的 OBJ，一次贴完：

- `arena_textured.obj`，35.3 MB，17.5 万顶点 / 37.9 万三角面，保留原 STL 坐标，
  补了法线，UV 用平面俯视投影
- `arena_textured.mtl` 里 `map_Kd rmuc2027_floor.png`，裸文件名
- 贴图 2800 × 1500，来自官方 2027 俯视图
- 世界文件里新增 world 级模型 `arena_textured`，原来 `model://rmuc_2027` 的
  include 停用（模型目录和 STL 都保留，只作形状基准）

命令记录：

```bash
cd ~/drone_sim/rm27_sim/models/rmuc_2027/meshes
# STL -> OBJ（保留坐标，补法线，按 28x15 比赛区做俯视 UV）
# 校验：面数与 STL 三角面数一致，包围盒不变
grep -c "^f " arena_textured.obj
```

`gz sim` 起来后场地一次性上色，围栏、台阶、立柱都在同一个网格里，没有接缝。

## 三条规律

1. 贴图 URI 在 `model://` 包含的模型内部会失效，必须挂到世界文件层级
2. OBJ 不带法线时 ogre 报 `No vertex normals found in TangentSpaceCalc`，整场变白
3. MTL 的 `map_Kd` 用相对文件名；绝对路径同样变白

## 试过但放弃的两条

- **5600 × 3000 上采样 + 锐化**：原图 31 px/m，插值出来的边缘发脆，
  近看比原图更糟，回退到 2800 × 1500。
- **竖直面平涂去拖影**：拖影确实没了，但整场的体积感也没了，整体观感更差，
  保留平面投影。

## 同日实机对照

同一天在实机上做了 VIO 内录分析（ORB-SLAM3 + PX4），和仿真这边的问题正好互补：

- VIO 输出本身不漂：静止 650 s 起终点重合，1220 s 那段只有 0.4 cm
- 快转掉高是真的：角速度拐点在 57°/s 附近，超过 115°/s 时下沉速率 −6.6 cm/s
- 输出频率随时间衰减（16.3 Hz → 5.5 Hz，10 分钟），排除热降频
- 内录脚本里 PX4 位置字段整体错位，EKF 位置不可用，只能靠 VIO 侧数据判断

仿真这边的价值就在这：位姿有真值，可以把"导航逻辑错"和"视觉退化"分开定位，
实机上混在一起的问题，先在仿真里拆干净。
