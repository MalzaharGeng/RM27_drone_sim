# 电调换向能力测试报告

> 测试日期：2026-11-19
> 测试对象：MicoAir743v2-AIO-35A（4 × 35 A Bluejay 0.19.2）
> 目的：确认这块板子的电调能否执行 DShot 方向命令 20/21，为翻正功能的「反向」出力层提供依据。

## 1. 结论先行

| 问题 | 结论 |
|---|---|
| Bluejay 认不认 DShot 方向命令 20/21？ | **认**，四个电机全部确认可反向 |
| 反向之后能不能立刻恢复？ | **能**，发命令 20 后下一个脉冲即恢复原方向 |
| 电机编号与 PX4 Quad-X 定义是否一致？ | **一致**（1/2 同向、3/4 同向且相反） |
| 会写坏电调 EEPROM 吗？ | **不会**，全程未发 save 命令（22），参数未改动 |
| 翻正功能能不能直接用了？ | **还不能**，换向时序尚未接入 DShot 驱动，见第 7 节 |

**一句话**：硬件这一关通过了，「高位反转、低位正转」在物理上可执行，剩下的只是驱动层时序。

## 3. 测量方法

### 3.1 为什么不能靠肉眼看

无桨状态下电机转速高、叶形不明显，肉眼判断转向主观且容易看错（第一次尝试就失败了）。
BSHOT 遥测在本板上不可用（`DSHOT_BIDIR_EN=0`，MicoAir 也注明 PX4 下不支持双向 DShot），
拿不到 eRPM 反馈。所以改用**机身反作用力矩**做客观测量。

### 3.2 原理

电机加速时角动量为零的机身会获得一个**大小相等、方向相反**的反作用力矩：

```
电机俯视逆时针加速  ->  机身受到俯视顺时针力矩
电机俯视顺时针加速  ->  机身受到俯视逆时针力矩
```

PX4 机体系为 FRD（x 前、y 右、z 下），绕 +z 的正向旋转在俯视视角下是**顺时针**。
因此抓 `zgyro` 在起步瞬间的脉冲符号，就能反推电机转向，不需要看、不需要听。

### 3.3 采集链路

```
actuator_test set -m N -v 0.30 -t 1.5      # 未解锁状态下给 30% 油门 1.5 s
        |
        v
HIGHRES_IMU.zgyro  @ 200 Hz 请求（实测约 140 Hz）
        |
        v
取 t = 0.20 s 附近的峰值符号
```

请求高频率：

```python
master.mav.command_long_send(
    target_system, target_component,
    511, 0,            # MAV_CMD_SET_MESSAGE_INTERVAL
    105,               # HIGHRES_IMU
    int(1e6 / 200), 0, 0, 0, 0, 0)
```

### 3.4 两次失败的方法（记下来避免重复踩）

| 方法 | 结果 | 原因 |
|---|---|---|
| 对 `gz` 做 0.3–1.3 s 积分 | `-0.47 mrad`，判不出方向 | 机身放在台面上，起步冲量被台面摩擦吸收后又回弹，正负抵消 |
| 取第一个超过阈值的单点 | 结果随油门波动，15% 时不可靠 | 单点受振动污染，起步前就有噪声尖峰 |

**有效判据**：把 0.05 s 分箱后的均值取峰值，看 0.20 s 那一格的符号。起步冲量集中在这一格，
稳态后 `gz` 回到 0 附近，信噪比最好（噪声底 2.3–2.5 mrad/s，信号 100–400 mrad/s）。

## 4. 数据

### 4.1 单电机 A-B-A（Motor 1，30% 油门）

| 阶段 | 0.20 s 处 `gz` | 峰值 `\|gz\|` | 判定 |
|---|---|---|---|
| 正常方向 | **+126 mrad/s** | 380 mrad/s | 电机俯视逆时针 |
| `dshot reverse -m 1` 后 | **−184 mrad/s** | 352 mrad/s | 电机俯视顺时针 |
| `dshot normal -m 1` 后 | **+103 mrad/s** | 399 mrad/s | 恢复逆时针 |

三次符号为 `+ / − / +`，且数值量级一致，符合「反向一次、恢复一次」的预期。

原始波形（0.05 s 分箱，单位 mrad/s，截取起步段）：

```
正常   0.10:+1   0.15:+0   0.20:+126  0.25:+19   0.30:-4   0.35:-5
反转   0.10:+1   0.15:+1   0.20:-184  0.25:-61   0.30:-13  0.35:-21
恢复   0.10:-0   0.15:-10  0.20:+103  0.25:+10   0.30:-2   0.35:-9
```

### 4.2 四路扫描（30% 油门，每路各自做完 A-B-A 后复位）

| 电机 | 正常方向 `gz` | 反转后 `gz` | 结论 | 正常转向（俯视） |
|---|---|---|---|---|
| 1 | **+233** | −267 | 可反向 | 逆时针 |
| 2 | **+271** | −328 | 可反向 | 逆时针 |
| 3 | **−349** | +275 | 可反向 | 顺时针 |
| 4 | **−290** | +202 | 可反向 | 顺时针 |

**4/4 全部确认可反向。**

### 4.3 顺带得到的两个结论

**① 电机编号与 PX4 标准 Quad-X 一致**

1、2 号同向（逆时针），3、4 号同向（顺时针）且与 1、2 相反——这正是 Quad-X 的转向布局。
说明 `CA_ROTOR0..3` 的编号与物理电机一一对应，翻正算法里用 `CA_ROTORn_PX/PY` 选高位/低位
不会错位。

**② 未解锁出力通道在官方固件里就是通的**

`actuator_test` 给 10% 油门时，`actuator_outputs.output[0]` 读到 **298**（其余通道为 0），
而此时 `armed=False`。这印证了 `MixingOutput` 里那条「测试模式绕开 armed 门控」的路径确实存在，
本项目 `setRecoveryOutputs()` 正是照它的形状实现的。

## 5. 对实现的影响

| 原假设 | 实测结果 | 影响 |
|---|---|---|
| Bluejay 支持命令 21 | ✅ 支持 | 「反向」不必退回人工换线序，功能可自动完成 |
| 只能走方向命令，不能用 3D 油门 | ✅ 确认（`DSHOT_3D_ENABLE=0`） | `MixingOutput` 里清 `_reversible_mask` 是必须的，不是可选项 |
| 方向命令可以随时发 | ⚠️ 只在**电机停转**时测过 | 驱动层必须实现「停机 → 发命令 → 等电调 → 再给油门」 |

## 6. 未验证的部分

| 项 | 为什么没测 | 怎么测 |
|---|---|---|
| 本分支固件的 override 与换向时序 | 本机无 ARM 工具链，飞控里是官方固件，且用户要求暂不刷写 | 编译刷入后 `FLIP_EN=1` + `commander mode flip` |
| 方向命令在电机旋转中是否被接受 | 规范要求停机发送，没必要冒险 | 如果时序实现正确，永不需要 |
| 断电后方向是否保持 | 每次都在同一会话内复位，未做断电重启对比 | 发 `reverse` 后断电重启，再测一次符号 |
| 完整翻正效果 | 依赖上面两项 | 台架低油门 → 带桨低推力 → 实飞 |

> 关于 EEPROM：BLHeli_S / Bluejay 的方向命令 20/21 只改 RAM，要持久化必须再发命令 22（save）。
> 本次全程未发 22，所以电调配置未被写入；即使有残留，断电重启也会回到原方向。

## 7. 下一步（驱动层时序）

在 `src/drivers/dshot/DShot.cpp` 里把 `flip_recovery_control.control[]` 的符号接上，需要三个阶段：

```
ACTION_DRIVE 到达
    |
    +-- 阶段 1 停机：所有通道输出 0，保持 ~100 ms
    +-- 阶段 2 换向：对 rev_mask 发命令 21、对 fwd_mask 发命令 20（各 10 帧）
    |               _current_command 一次只能一个 mask，所以两组要分两轮发
    +-- 阶段 3 出力：按 control[] 的绝对值给油门
    |
ACTION_STOP / 话题超时
    +-- 输出 0，对所有曾反向的电机补发命令 20，清方向状态
```

细节见 [`README.md` 第 8 节](README.md)。

## 8. 复现步骤

```bash
# 0. 拆桨，接电池，USB 连飞控（本机为 COM11）

# 1. 确认 DShot 驱动在线、四路输出已启用
dshot status

# 2. 电流声测试：确认 DShot 命令帧能到达电调（应听到一声）
dshot beep1 -m 1

# 3. 基准：正常方向给 30% 油门 1.5 s，观察 zgyro 起步脉冲符号
actuator_test set -m 1 -v 0.30 -t 1.5

# 4. 反向，重复第 3 步，符号应翻转
dshot reverse -m 1

# 5. 复位，重复第 3 步，符号应恢复
dshot normal -m 1

# 6. 四路一起复位
dshot normal
```

采集脚本核心逻辑（约 30 行，可直接跑）：

```python
from pymavlink import mavutil
m = mavutil.mavlink_connection('COM11', baud=115200)
m.wait_heartbeat()
m.mav.command_long_send(m.target_system, m.target_component, 511, 0,
                        105, 5000, 0, 0, 0, 0, 0)   # HIGHRES_IMU 200 Hz

# 触发油门后，统计 0.20 s 附近 zgyro 的均值
```
